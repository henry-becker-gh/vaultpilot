Environment: Debian container, 8 cores, Agave CLI v2.1.21 toolchain
(platform-tools cargo/rustc 1.79), Node v22.14.0, @solana/web3.js 1.99.0
(with `overrides: { "rpc-websockets": "9.3.10" }` — see note at bottom).
Dependency pins in `program/Cargo.toml` + `Cargo.lock` keep the whole graph on
edition-2021 manifests so the Solana platform-tools rustc (1.79) can build it
(fresh `cargo update` pulls e.g. `cmov 0.5.x` which requires edition2024).

```
RESULT: 6 passed, 0 failed
```

What the checks prove:
- **policy validation**: `initialize` with shares summing to 9 000 bps is rejected
  on-chain with custom error 0x1 (the tx fails in the program, not the client).
- **atomic split**: a 1.5 SOL deposit produces exactly 1.05 / 0.30 / 0.15 SOL in
  the three share PDAs (asserted on-chain via `getBalance` deltas AND via the
  program's return data), the vault is left with zero deposit residue.
- **no dust loss**: 777 777 lamports → 544 443 / 155 555 / 77 779 (floors + dust
  to treasury; sums back to exactly 777 777).
- **audit trail**: split-record PDAs exist for deposits #0 and #1, #2 is null —
  history is enumerable and immutable.
- **attack resistance**: pointing `deposit_and_split` at an attacker-chosen
  "vault" account is rejected with custom error 0x4 (BadVault).

## Note: @solana/web3.js and rpc-websockets

A fresh `npm install @solana/web3.js@1` currently resolves `rpc-websockets`
9.3.9, whose CJS build requires ESM-only `uuid@14` and crashes on import. The
`overrides` field in `package.json` pins `rpc-websockets` to 9.3.10 which fixes
it. Committed together with `package-lock.json` so fresh installs reproduce.
